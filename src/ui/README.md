# src/ui — 网页界面

React + SVG 界面。**只负责显示状态与产生 Action，从不修改游戏状态。**

## 操作模型（4.8：交互减法）

1. 点击角色卡或地图上的角色 → 选中，地图立刻高亮**可达节点**与**可攻击的敌人**；
2. **单击即执行**：点一下高亮节点就是移动，点一下高亮的敌人就是普攻；技能是**选中角色后浮在卡牌上方**的那颗圆钮（外圈是 CD 环，无目标的技能点一次即施放，有目标的进入瞄准）；
3. 手牌同一套规则：选牌 → 高亮合法目标 / 落点 / 边 → 点一下执行；
4. **取消**：再点一次已选中的卡（或按 Esc、点地图空白处）；
5. **悔棋**：顶栏的「悔棋」按钮可以回退上一步——这是本地对局的便利功能，不是游戏规则（联机不可用）；
6. 只有"还需要再选一个参数"的情况才出现浮动层（弃牌、净化选状态）。

> 「移动 0 格」是规则允许的（`RULES.md` §8.1，等价于放弃这次移动），但界面**不给这个落点**：
> 单击即执行的模型下点到自己脚下等于白扔一个行动，想放弃请用顶栏的「放弃行动」。
> 技能里的"移动 0 格"（Spica 星奔）不受影响，那颗圆钮照旧可用。

## 对局记录 / 回放（开发面板里）

- `replay.ts` 把一局压成 **种子 + 行动序列** 的 JSON（引擎是确定性的，所以能逐帧重现）。
- `transport.ts` 里：`record` 实时给出当前这一局的 JSON，`loadRecord / replayStep / replayBack / stopReplay`
  负责载入与逐步回放；**回放期间 App 会把 legalActions 置空**，棋盘不可操作，看完可以「结束回放」接着玩。
- 面板入口在「开发面板 → 对局记录 / 回放」：复制记录发给协作者，或把别人的记录粘进来逐步重放。

## 数据流

```
GameTransport（transport.ts）
   ↓ getSnapshot(): { view: PlayerView, legalActions: Action[] }
App（App.tsx）＋ interaction.ts（高亮与"点两次"的判定）
   ↓ components/* 渲染
确认 / 第二次点击 → transport.dispatch(action)
```

## 文件

| 文件                | 职责                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| `App.tsx`           | 应用外壳：顶栏（对手）/ 地图 / 底部卡牌轨道与行动条                                                     |
| `transport.ts`      | **UI 与引擎的唯一通道**：快照（视图 + 合法行动）与 dispatch                                             |
| `useGame.ts`        | 把 transport 接进 React（`useSyncExternalStore`）                                                       |
| `interaction.ts`    | 交互状态机：点击 → 瞄准 → 执行；所有可点目标都从合法行动推导                                            |
| `tokenTrail.ts`     | 位移轨迹：把 MOVED / SWAPPED 事件翻译成 token 该走的那条线（纯函数）                                    |
| `motionTiming.ts`   | 动画节奏常量与纯函数：每跳时长、撞击时长与起手延迟、动画窗口                                            |
| `useTokenMotion.ts` | 用 Web Animations API 让 token 沿轨迹逐跳走过去（见下）                                                 |
| `portraits.ts`      | 立绘资源与**取景参数**（focusX / focusY / heightRatio，可逐个角色调）                                   |
| `formatEvent.ts`    | 把引擎事件/行动翻译成日志文字                                                                           |
| `theme.ts`          | 颜色、地图坐标与元素尺寸。阵营色/状态色各有"粉彩版"（地图、深色牌面）与"深色版"（浅色面板上的文字）两套 |
| `styles/`           | 全部样式，按 `@layer` 分层组织（见下）                                                                  |
| `i18n/`             | 全部面向玩家的文案                                                                                      |
| `components/`       | 展示组件（角色卡、立绘、地图、手牌、详情、行动条…）                                                     |

## 样式结构（`styles/`）

优先级由 `layers.css` 里声明的层顺序决定，**和文件顺序、书写位置无关**：

```
tokens < base < layout < board < cards < panels < screens < responsive
```

| 文件             | 层         | 内容                                                             |
| ---------------- | ---------- | ---------------------------------------------------------------- |
| `layers.css`     | —          | 入口：声明层顺序，按层汇总（`main.tsx` 只引入它）                |
| `tokens.css`     | tokens     | 颜色 / 圆角 / 阴影 / 布局常量，颜色只在这里定义                  |
| `base.css`       | base       | 重置、页面底色、按钮与标签等通用控件                             |
| `layout.css`     | layout     | 应用骨架、顶栏、队伍条、右侧栏                                   |
| `board.css`      | board      | 地图 SVG（边 / 节点 / token）、棋盘浮层、特效                    |
| `cards.css`      | cards      | 底部扇形、角色牌、功能牌                                         |
| `panels.css`     | panels     | 详情面板（含卡牌旁的就地展开）、行动记录、开发面板               |
| `screens.css`    | screens    | 开局界面、结算横幅                                               |
| `responsive.css` | responsive | 所有 `@media`（宽屏 ≥1101 / 窄屏 ≤900 / 矮屏 ≤680 / hover 设备） |

两条硬性约定：

1. **每个选择器全文件只出现一次**，状态（`:hover` / `--selected` / `--dead`）写进同一个规则块，
   不要靠"后面再写一条"去覆盖。
2. **所有规则都必须包在 `@layer` 里**；没进层的规则优先级高于所有层，会静默盖掉一切。
   另外牌面元素别写 `background` 简写（会盖掉 `card.png`），理由见 `base.css` 的"卡面例外"。

## 硬性约束

1. **UI 不直接读 GameState**：只能通过 `transport.getSnapshot()`。
2. **不复制规则**：可点目标全部来自 `legalActions`，因此不可能提交非法动作。
3. **不硬编码文案**：所有文字来自 `i18n`。
4. **UI 私有状态**（选中角色、待瞄准目标）不进 GameState。

## 桌面（4.5 起）

- 角色卡与手牌都是**牌面**（`assets/ui/card.png`），以扇形浮在地图之上：左右两张略微外倾、鼠标悬停抬起。
- 点击角色卡 = 选中；卡片右下角的圆钮 = 技能（外圈是 CD 环）。
- 选中某张牌时，**详情就地展开在它旁边**（靠右的牌翻到左边）；点一下空白或再点一次该牌即可收起。
- 地图可滚轮 / 拖拽缩放，选中时自动取景到作用范围并轻微倾斜；右侧栏常驻的是行动记录。
- **不再有部署界面**：开局由核心随机部署（见 `RULES.md` §3），界面直接进入战斗。

## 表现（4.4）

- **角色沿边逐跳移动**：引擎结算完时 token 的静态坐标已经是终点，`useTokenMotion` 只是用
  Web Animations API 给它叠一个临时位移，让它沿 `createMovePathOf` 算出的路径一个节点一个节点走过去
  （每跳 250ms，末尾留一点"站定"，跳起时略微放大）。动画不写 React 状态、结束不留残余
  transform，所以引擎状态永远是唯一真相；`prefers-reduced-motion` 下直接瞬移。
- **攻击撞击**：单体伤害时出手方会朝目标冲过去撞一下，目标被顶开一点点再弹回；AOE（同一次出手打了
  多个目标）和陷阱这类没有出手角色的伤害不做。撞击动画走 token 的**内层** `g.token__lunge`，
  走位在外层，所以"先移动后攻击"（星奔）时两者能叠在一起。
- 节奏常量集中在 `motionTiming.ts`（每跳 / 撞击时长、起手后仰、错开量、动画窗口）。
  同一批事件里既走位又打人时，**撞击会等走位走完**，伤害飘字与命中环也跟着延后。
- 这条路径和引擎的"移动距离"用同一套约束（`RULES.md` §8.1）：**绕开封路与敌方角色**
  （友方可以穿过）。少了这两条会画出"贴着封路甚至穿过敌人"的路线，演出就和规则对不上了。
- 换位（Lily 的技能）走对穿直线，不绕图。
- 移动轨迹（虚线）由 `EffectsLayer` 画在下面当"走过的路"，角色本身才是移动的主角。

## 立绘与取景

- 原图放在 `assets/characters/*.png`，地图用的小图在 `assets/characters/token/`（由 `node tools/make-thumbnails.mjs` 生成）。
- 觉得某个角色的头像裁切不对，改 `portraits.ts` 里那一个数字即可（`focusY` 往上/往下）。
- 没有素材时会自动退回字母圆形，不会崩。
